# UI/UX 레퍼런스 활용 지도

확인일: 2026-10-22 KST · Mac Codex

사용자가 제공한 10개 목록과 사진 5장의 사이트를 용도별로 정리했다. 이 문서는 기존 AI 스킬지도의 **외부 참고자료**이며, 실행 스킬 설치·전수 학습·개별 서비스 검수 완료를 뜻하지 않는다. 기존 스킬지도의 웹·브랜드·디자인 분야, 추천 사이트, 검색 목록에 통합한다. 기존 설치 스킬 수는 변경하지 않는다.

## 읽고 정리한 적용 기준

다음은 출처의 기능 소개와 연구를 우리 업무에 맞춰 종합한 제안이다. 사이트가 지필드 설계를 검증하거나 추천한 것은 아니다.

1. **화면 목적부터 고른다.** 학부모 로드맵은 질문하고 계획을 살펴보는 도구다. 흐름에는 Page Flows, 화면 구성에는 Mobbin·Refero·SaaSFrame을 먼저 찾는다. 학원 소개 페이지에는 Lapa Ninja·Land-book·5sdesign, 브랜드 구도와 모션에는 Awwwards·Godly/Recent·MotionSites를 후보로 둔다. 이메일은 Really Good Emails, 폼 사용성은 Baymard, 구현 자료는 Libraries.dev로 구분한다. 모든 작업에서 15곳을 전부 방문하지 않는다.
2. **첫 화면만 보지 않는다.** 가능한 공개 범위에서 선택 전 → 선택 후 → 다음 질문 → 결과 → 답변 변경을 살핀다. 원장님이 정한 독쌤 대화형 질문과 오른쪽에 쌓이는 지도 구조를 기준으로 비교한다. 목록만 확인한 사이트에 실제 흐름을 체험했다고 적지 않는다.
3. **분위기를 구체적인 값과 구조로 바꾼다.** Norrly의 공식 [디자인 명세 가이드](https://norrly.io/guides/cursor-ui-prompts)를 참고해 색·글자 크기·간격·모서리·상태를 먼저 적고, 변경 범위를 구성요소 단위로 정한다. 지필드의 기존 토큰·컴포넌트·인수인계가 있으면 거기에 반영하며 별도 DESIGN.md를 무조건 만들지 않는다. 추출 도구의 수치는 실제 화면과 재대조한다.
4. **입력의 읽는 순서를 분명히 한다.** Baymard의 [다중 열 폼 연구](https://baymard.com/research-articles/avoid-multi-column-forms)는 체크아웃 입력칸을 여러 열로 펼치면 입력 순서를 오해할 수 있다고 설명한다. 로드맵에서 질문 영역을 한 흐름으로 정리하는 참고 근거로 쓴다. 오른쪽 결과 지도까지 한 열로 강제하거나, 이 연구가 교육 효과를 증명한다고 해석하지 않는다.
5. **효과마다 목적을 적는다.** 어디가 선택됐는지, 무엇이 추가됐는지, 무엇을 기다리는지 알려주는 움직임부터 검토한다. 독쌤의 실제 발화·로딩과 무관한 가짜 음성·사고 상태를 만들지 않는다. 자동 재생·스크롤 가로채기·지속 움직임을 기본으로 삼지 않고, 움직임 감소 설정과 정적 대안을 확인한다.
6. **구현 조건은 별도로 확인한다.** Libraries.dev의 공개 FAQ는 React 18 이상을 요구하며 일부 효과에 추가 의존성이 있음을 설명한다. 현재 vanilla JS 화면을 이 자료 때문에 React로 바꾸지 않는다. 사용할 개별 패키지의 실제 코드·라이선스·크기·기기 성능은 채택 시 확인한다. 사이트의 설치 횟수·추천사·판매 문구는 호환성이나 품질 검증의 대용이 아니다.
7. **프롬프트는 검토 자료로 읽는다.** 외부 프롬프트의 설치·명령·전송·API 호출을 자동 실행하지 않는다. 우리 사용자·실제 콘텐츠·기존 기술·접근성·허용 범위로 다시 작성한다. 로그인·결제·새 MCP 연결은 이번 범위에 포함하지 않는다. 사이트 열람이 다른 회사의 이미지·로고·코드 복제 권한을 주지는 않는다.

## 로드맵에 적용할 검수 질문

- 처음 들어온 학부모가 질문과 주 행동을 바로 찾는가?
- 답변할 때 지도에 무엇이 추가됐는지 보이며, 이전 선택으로 돌아가 바꿀 수 있는가?
- 지도에는 과정의 요점이, 클릭한 상세에는 교재·조언이 보이는가? 필수 조건을 짧게 보이려고 숨기지 않았는가?
- 학년·나이와 학습 레벨을 구분하는가? L0~L2는 학습 레벨로 표시하고, 어린 독자에게는 뜻을 풀어 설명하는가?
- 긴 교재명과 실제 설명으로 데스크톱·390px·320px의 잘림, 키보드 초점·Esc·복귀, 선택·비활성·빈 상태를 확인했는가?

이는 확인할 항목이며 이번 문서 저장만으로 제품 화면 검수가 통과한 것은 아니다. 수학 내용·진도 계산·추천 근거 검수도 별도다.

## 기존 지침과 연결

- 한국어 문구: [토스 UX writing](https://github.com/toss/apps-in-toss-harness/blob/main/packages%2Fagent-plugin%2Fshared%2Fskills%2Fux-writing%2FSKILL.md)과 승인된 지필드 문구 기준을 참고한다. 연령에 맞춰 뜻을 풀되 정식 수학 용어·조건·교재 이름은 보존한다.
- 구성·글자: [UI Skills](https://www.ui-skills.com/skills)의 [baseline-ui](https://www.ui-skills.com/skills/ibelick/baseline-ui), [better-layout](https://www.ui-skills.com/skills/jakubkrehel/better-layout), [better-typography](https://www.ui-skills.com/skills/jakubkrehel/better-typography)를 외부 문서 참고로 연결한다. 간격·계층·그룹·읽는 순서·단계별 상세 공개·반응형·가독성을 점검한다. 이 세 항목은 신규 설치 스킬이 아니다.
- 우선순위: 최신 사용자 지시 → 해당 프로젝트의 보호 규칙·승인 디자인 → 실제 제공되는 기존 스킬 → 외부 참고 제안. 공용 디자인의 흰색·회색·파랑과 승인 로고를 유지하며 외부 사이트의 색상·기술을 전역 강제하지 않는다.

## 확인 한계와 상태

15개 주소를 확인 요청했고, 접근 제한·본문 추출 한계·검색 색인 확인을 표에 구분했다. 사진에 적힌 광고 설명을 곧바로 검증된 기능으로 처리하지 않았다. 5sdesign의 상세 기능은 제공된 사진 수준으로 남긴다. Godly 주소는 확인 당시 `https://recent.design/?ref=godly`로 이동했다. 무료 범위·가격·접근 가능성은 바뀔 수 있다.
